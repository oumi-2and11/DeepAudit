# 选题要求：基于大模型智能体的开源项目安全缺陷自动审计和验证系统

> 组队规模：6–10 人 / 组（我们组选择 **题目一**）

---

## 一、实验背景

随着大语言模型（LLM）技术的快速发展，基于 LLM 的智能体（Agent）已经能够在代码安全审计领域发挥越来越重要的作用。当前，由自主 LLM 智能体完成的审计已在关键基础软件中发现大量高危漏洞。业界已涌现出 **DeepAudit、AgentStalker、OpenSecurity、deepfake** 等多个开源或商业化的智能体安全审计系统。

然而，直接使用大模型进行代码审计仍面临三大核心挑战：

1. **误报率高**
2. **缺乏证据链**
3. **结果不可复现**

如何构建一个 **可审计、可验证、可复现** 的自动化安全缺陷审计系统，是该领域的核心研究问题。

要求学生综合运用 **智能体设计、代码分析与漏洞验证** 等技术，构建一个能够对开源项目进行自动安全审计和漏洞验证的端到端系统。

---

## 二、实验目标

1. 理解并实践大模型智能体的设计与开发流程。
2. 构建一个 **多智能体协作** 的安全审计系统，实现从代码扫描到漏洞验证的完整链路。
3. 培养系统性解决复杂工程问题的能力。

---

## 三、系统功能要求

> 以下为参考性要求，不限制新的思路和新的功能。

### （1）代码仓库解析模块

- a) 支持输入 **GitHub / GitLab 仓库 URL** 或本地代码目录；
- b) 自动识别项目 **编程语言**；
- c) 提取项目 **文件结构、依赖关系** 等元信息。

### （2）智能体审计模块（核心）

基于大模型，构建 **至少多个协作智能体**：

- a) **扫描智能体**：负责对代码进行静态分析，识别潜在的
  - SQL 注入
  - 命令注入
  - 路径遍历
  - 硬编码密钥
  - 等其他安全风险
- b) **验证智能体**：对扫描结果进行独立复核，过滤误报。

> 智能体需具备 **工具调用能力**（如调用 SAST 工具、执行代码分析脚本等），例如采用 **MCP + Skills** 架构。

### （3）漏洞自动利用模块

- 对于验证存在的安全漏洞，实现 **自动化的漏洞利用**，形成漏洞利用（PoC / Exploit）代码。
- 输出每个漏洞的 **证据链**，包含：
  - 文件位置
  - 调用路径
  - 验证结果

### （4）报告生成模块

自动生成 **结构化的审计报告**，报告需包含：

- 漏洞列表
- 严重等级
- 证据链
- 修复建议

## 四、开源参考项目对比

通过对比其他开源项目，验证在某些方面 **自研系统的创新性**：

| 编号 | 项目 | 特点 |
| ---- | ---- | ---- |
| 1 | **DeepAudit** | 国内首个开源的代码漏洞挖掘多智能体系统，支持自主协作审计 + 自动化沙箱 PoC 验证 |
| 2 | **AgentStalker** | 首个将 LLM 智能体作为系统进行端到端安全审计的框架，包含 **静态建模 → 攻击图合成 → 沙箱动态验证 → 证据裁决** 的完整流程 |
| 3 | **OpenSecurity** | AI 驱动的多领域安全分析 Agent 平台，LLM 可自主编排工具链完成端到端安全分析 |
| 4 | **ESAA-Security** | 事件溯源架构的安全审计系统，将安全审计视为确定性流水线而非自由格式清单 |
| 5 | **Sandyaa** | 自主代码审计工具，可递归深入挖掘直到发现并证明真实漏洞 |
